## 1. 项目当前结论

Moe Social 当前不是单一社交 App，也不是单一 AI 工具，而是一个已经形成基础产品骨架的复合型项目。

当前真实形态主要由四条线组成：

- 萌系社交主线
- AI 智能体 / 酒馆化能力线
- 虚拟形象 / 礼物 / VIP / 资产玩法线
- AutoGLM 自动化实验能力线

当前最核心的问题，不是“功能太少”，而是：

- 主线很多，但收束还不够
- 文档与实现曾经不同步
- 一部分功能已可用，一部分仍是骨架态
- AI 线有潜力，但还没有完全服务于社交主目标

一句话判断：

**这是一个社交骨架已成型、AI 能力正在快速增强、但产品主价值仍需要继续收束和强化的项目。**

## 2. 当前已经完成的部分

### 2.1 社交基础能力

已具备：

- 登录 / 注册 / 用户资料
- 动态流 / 发帖 / 评论 / 点赞 / 话题
- 关注 / 粉丝 / 好友请求 / 好友列表
- 私信 / WebSocket / 在线状态
- 群组 / 社区基础能力
- 通知中心

判断：

- 这部分已经构成真实社交产品骨架

### 2.2 成长与商业基础

已具备：

- 签到
- 等级
- 成就
- 钱包
- VIP 中心
- 充值入口
- 交易记录

判断：

- 结构完整，但商业闭环仍偏早期

### 2.3 AI 能力

已具备：

- AI 智能体列表
- 智能体编辑
- 聊天页
- 内容生成页
- Provider Profile
- OpenAI-compatible / 中转站接入
- Lorebook / 世界书基础能力
- 角色卡字段扩展
- 默认角色模板 / 默认世界书模板
- 统一 Chat Gateway

判断：

- AI 已经不是展示页，而是实装中的子系统

### 2.4 AI 后端化与架构修正

已完成：

- AI 配置与资源改为 `API -> RPC -> DB`
- API 层不再直接访问数据库
- RPC 层负责 AI 配置与资源数据库读写
- `super.proto` 已同步更新
- pb 代码已重新生成
- 后端已通过编译

当前服务端接口包括：

- `/api/ai/config`
- `/api/ai/providers`
- `/api/ai/agents`
- `/api/ai/lorebooks`

## 3. 当前正在进行中的部分

正在推进，但还没完全闭环的内容：

- AI 页面酒馆化改造
- Provider 来源标识与默认选择体验
- User Persona 联动
- Lorebook 与聊天链路的更强整合
- 角色卡导入导出的进一步兼容
- 文档与代码状态对齐

## 4. 当前明显还缺的部分

### 4.1 AI 线缺口

- 第三方 Provider 聊天链路尚未完全后端统一代理
- 会话侧边栏与分支会话未完成
- 多角色群聊未完成
- 角色卡生态兼容仍不完整
- Provider 能力画像未完整产品化
- 页面风格还不够像成熟酒馆类 App

### 4.2 社交主线缺口

- AI 与社交主线结合还不够深
- 虚拟资产、礼物、商城的数据闭环还不完整
- 一些能力仍停留在演示态或 mock 态

### 4.3 工程与管理缺口

- 文档虽然已开始补齐，但仍需要持续维护
- 还缺一份长期稳定的“当前真相文档”
- 部分旧说明文档仍可能存在过时描述

## 5. 当前是否偏离项目目标

### 5.1 没有完全偏离

项目仍然保留了“萌系社交 + 虚拟表达 + AI 增强”的主方向。

社交主骨架没有丢，AI 线也不是完全无关的外挂。

### 5.2 但存在偏离风险

偏离风险主要在两处：

- AutoGLM 这类能力容易把产品拉向“工具箱”
- AI 智能体如果完全独立发展，容易变成与社交并列的第二产品

更合适的方向应是：

**让 AI 服务社交，而不是让 AI 与社交并列竞争主入口。**

## 6. 当前是否具备创新性

有，但创新点还没有完全收束成卖点。

当前可成立的创新组合是：

- 萌系社交
- 虚拟形象表达
- AI 角色陪伴 / 角色聊天
- 用户记忆 / Persona / 世界书

如果继续做好，项目会更像：

**带有酒馆式 AI 角色能力的萌系兴趣社交产品**

而不是普通社区 App，也不是普通 AI 聊天壳。

## 7. 当前建议的优先级

### P0

- 完成 AI 线核心体验闭环
- 稳定 Provider 选择、来源展示、配置持久化
- 修正聊天注入逻辑，使其适配角色卡 / 酒馆式使用方式

### P1

- 补 User Persona
- 补会话侧边栏
- 补默认模板入口和空状态引导
- 继续重做 AI 首页与编辑页视觉风格

### P2

- 补角色卡生态兼容
- 补多角色群聊
- 补高级预设与扩展能力

### 不建议现在优先做

- 先做完整插件系统
- 先把所有第三方能力都做成一级主入口
- 先扩成一个庞杂的 AI 工具集合

## 8. 推荐的产品落点

当前更建议把项目收束为：

**以兴趣社交为主轴，以萌系虚拟表达为差异化，以 AI 角色聊天与记忆能力作为增强层。**

对应到产品表达上：

- 主产品不是“AI 工具”
- 主产品也不是“自动化工具箱”
- 主产品应是“社交 + 表达 + 陪伴”
