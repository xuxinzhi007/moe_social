## 3. 联调修复记录（2026-05-19）

与 P0–P2 同期或紧随其后的问题修复，已合入主线。

| 问题 | 原因 | 处理 |
|------|------|------|
| 输入区双停止钮、输入框过大 | 生成条与输入内停止重复 | `stopControlInBanner: true`，输入区仅 spinner |
| 第三方 `openai_error` 400 | P2 对 Codex 传 `temperature` | `supportsSamplingParams()`，codex/o 不传采样参数 |
| HTTP 200 仍失败 | `content: ""` 空回复 | 明确「空回复」异常与界面文案；尝试读 `reasoning_content` |
| 失败后再发更易挂 | 失败气泡当 assistant 进历史 | `_buildChatApiHistory()` 过滤错误类消息 |
| 看不到 Provider 日志 | 仅后端 `/api/llm` 打日志 | 第三方请求增加 `📤/❌ [Provider]` |
| 记忆「没作用」 | 未登录 / 终端模式 / 双轨不透明 | 状态条 + 设置 Sheet 说明；注入走 display API |

## 4. 记忆系统（行为说明）

| 场景 | 注入 | 提取 |
|------|------|------|
| **服务器 Ollama** + 已登录 | 服务端 `/api/llm/chat` 自动注入 | 服务端异步提取 |
| **我的 API（第三方）** + 已登录 | 客户端 `enrichSystemPromptWithMeta` | 回合后 `extractAndUpsertServerMemories` + 标签兜底 |
| **未登录** | 不注入 | 不写入 |
| **终端调试模式**（`/api/llm/chat/raw`） | 关闭 | 关闭 |

UI：`AppBar` 调谐入口 → 对话设置；身份条 `记忆·已注入 N 条` / `服务端·N条`；发送后约 3s 刷新记忆条数。

## 5. Provider / 模型排错（用户向）

| 日志/现象 | 含义 | 建议 |
|-----------|------|------|
| `400` + `openai_error` | 中转或上游拒绝请求 | 查 Key、余额、模型 ID；Codex 勿带 temperature（已修） |
| `200` + `content:""` | 接口成功但无可见正文 | 新建对话；角色扮演换 `gpt-5.2`/`gpt-5.4`，少用 codex |
| `temperature=default` | 未向 Codex 发 temperature | 正常 |
| `/models` 成功但 chat 失败 | 列表与对话能力不一致 | 在角色编辑改「绑定模型 ID」 |

切换模型路径：**角色列表 → 编辑角色卡 → 模型与来源 → 绑定模型 ID / 点芯片 → 保存**（聊天页暂不支持直接换模）。
