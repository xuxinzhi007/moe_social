# 数字生命生态沙盒演进方案

## 1. 背景

当前“数字生命”系统已经具备以下基础能力：

- 后端常驻 `tick` 引擎
- 实体缓存、异步持久化、WebSocket 广播
- 前端实时地图、事件流、实体详情页

但目前的核心能力依然偏基础：

- 实体主要是简单移动
- 行为主要由饥饿、精力、情绪等少量状态驱动
- 地图更像展示舞台，而不是会真实影响生命的世界

这与“生命世界”的目标还有明显差距。

## 2. 产品目标

把当前系统从“生命演示器”升级为“生态沙盒观察世界”。

目标不是直接复制 `Noita`，而是借鉴它的核心思路：

- 世界由底层规则驱动
- 每次启动都能生成不同生态
- 生命行为由环境压力涌现
- 世界与生命相互塑造

## 3. 设计原则

### 3.1 规则驱动优先于模板驱动

不优先硬编码“这个角色现在该做什么”，而是先建立：

- 世界资源
- 地形阻力
- 危险区域
- 生命周期压力

让行为从系统中自然出现。

### 3.2 先做轻量生态，再做重型像素演算

第一阶段不直接上逐像素材料流动、燃烧、腐蚀系统。

先做：

- 网格化世界
- 地形与资源层
- 资源再生与枯竭
- 出生、觅食、衰弱、死亡
- 群体数量与生态统计

先建立“世界在活着”的真实感。

### 3.3 复用现有基础设施

继续复用：

- `LifeEngine`
- `WorldCache`
- `PersistenceWriter`
- `/api/life/*`
- `/ws/life`

避免推倒重做。

## 4. 阶段规划

## 阶段一：生态沙盒骨架

目标：从“简单移动”升级为“有资源与生态反馈的世界”。

### 后端

- 世界快照中加入网格世界层
- 每个 cell 持有：
  - 地形类型
  - 食物资源
  - 水分
  - 危险度
- 每个 tick 执行：
  - 资源再生
  - 资源衰减
  - 实体按当前位置消费资源/移动
  - 世界摘要统计更新
- 输出世界摘要：
  - 总资源
  - 可居住格数量
  - 高危区域数量
  - 种群数量

### 前端

- 页面显示世界摘要
- 地图支持叠加资源热力感
- 保持现有实体卡片和事件流兼容

### 验收信号

- 同一个世界里，不同区域资源不同
- 实体行为和资源分布开始相关
- 世界会自己“长”资源，也会被消耗

## 阶段二：生命循环与演化

目标：引入出生、衰弱、死亡、代际差异。

### 后端

- 实体加入：
  - `age`
  - `alive`
  - `species`
  - `fertility`
  - `metabolism`
  - `perception`
- 引入规则：
  - 繁衍
  - 老化
  - 死亡
  - 后代轻微变异
- 增加生态事件：
  - `birth`
  - `starvation`
  - `collapse`
  - `migration`

### 前端

- 时间轴展示出生/死亡事件
- 可观察某个族群数量变化
- 支持查看单个实体“家族线”

### 验收信号

- 世界里出现代际更替
- 有的区域繁荣，有的区域衰退
- 不同个体出现明显行为差异

## 阶段三：轻量 Noita 化

目标：增强世界交互深度和展示力。

### 后端

- 引入轻量材料系统：
  - 水
  - 火
  - 毒雾
  - 孢子
  - 腐蚀液
- 采用局部扩散，而非全图逐像素演算
- 让生命与材料产生双向作用

### 前端

- 材料层动态叠加显示
- 支持用户投放某种扰动
- 提升观察感和可玩性

## 5. 第一阶段技术方案

### 5.1 世界模型

在 `WorldSnapshot` 中新增：

- `Grid`
- `Summary`

其中 `Grid` 为固定尺寸二维网格，建议先用 `32 x 18`。

每个 cell 包含：

- `terrain`
- `food`
- `moisture`
- `danger`
- `habitable`

### 5.2 实体与世界关系

实体坐标继续保持现有连续坐标：

- `PositionX`
- `PositionY`

但在 tick 中映射到所在网格 cell。

后续行为逻辑优先读取当前 cell：

- 饥饿时优先消耗当前 cell 的 `food`
- 危险区域会压低 `mood`
- 高资源区域更容易停留与聚集

### 5.3 生态摘要

每个 tick 统计：

- `entity_count`
- `avg_hunger`
- `avg_energy`
- `avg_mood`
- `total_food`
- `habitable_cells`
- `danger_cells`

摘要可用于：

- 前端仪表信息
- 后续 admin 可视化
- 历史趋势分析

### 5.4 实现顺序

1. 后端新增网格世界结构体
2. 初始化世界时生成资源层
3. tick 中执行资源再生与环境影响
4. REST / WS 输出生态摘要
5. 前端展示摘要卡片

## 6. 当前实现边界

本次启动实现不直接做：

- 像素级材料模拟
- 完整遗传系统
- 持久化网格存储
- 用户干预动作系统

本次重点是先把“世界”做出来。

## 7. 本次落地目标

本轮代码实现聚焦阶段一骨架：

- 后端世界网格与生态摘要
- tick 中的资源再生与环境影响
- 前端读取并展示世界摘要

这样可以尽快把“简单移动”推进到“生态世界雏形”。

### 8.4 当前还缺什么

虽然骨架已经搭起来了，但现在更像“能运行的生态雏形”，距离“有真实观察感的世界”还差几步：

- 地图还没有明显的资源热区 / 危险区可视化
- 用户还不能一眼看懂哪里富饶、哪里危险、哪里在衰退
- 生命个体之间的代际差异还不够明显
- 出生、死亡、迁移这些变化还不够有冲击力

### 8.5 下一步计划

短期下一步：

- 给地图补充轻量资源/危险热区叠加
- 强化事件流的可读性
- 让“世界状态”不只在数字上可见，也在空间上可见

中期下一步：

- 进入阶段二生命循环
- 增加 `age / alive / fertility / metabolism / perception`
- 引入更明确的繁衍、老化、死亡和轻量变异

### 8.6 当前结论

这一轮不是推翻重做，而是在现有数字生命引擎上，已经成功迈出从：

- 简单移动展示

到：

- 生态世界雏形

的关键一步。后续重点会转向“世界可观察性”和“生命循环演化”两条线并行增强。
