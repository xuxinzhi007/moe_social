## Persona

**阿星**，26 岁，陪伴需求型用户，愿意为爱付费

- **情境**：通勤/睡前/独处时想说话、想看看"TA 们"在干嘛
- **目标**：与一个记得共同经历的 TA 维持长期关系，并在关系里有"一起做的事"
- **当前 workaround**：Character.AI/星野聊天（角色没有自己的生活）+ 独立卡牌游戏（与陪伴割裂）
- **挫败感**：AI 聊完就停；关系没有可视化沉淀；游戏成就没有社交出口；付费点单薄
- **"完成"长什么样**：每天打开能看到 TA 的新动态、世界在往前走、关系有积累

次要 persona：**小莓**（轻社交记录型，见总 PRD §3）——她的缺口集中在冷启动与内容分发。

## 商业角度

- **为什么是现在**：功能面已完整，进入"验证留存"阶段；AI 陪伴赛道付费意愿已被验证但形态趋同，共享世界是无人在走的开口；个人开发者必须把钱花在有差异化的刀刃上。
- **谁付费**：陪伴型用户直接付费（VIP/礼物/星晶消耗）；社交用户间接贡献内容与关系链。
- **商业化**：订阅（VIP）+ 虚拟经济（星晶/礼物/装扮）双轨；LLM 成本是主要可变成本，活世界成本护栏（K3）是商业模式成立的前提。
- **战略意图**：retention 为主（留存驱动收入增长），growth 为辅。

## 桌上的方向

**方向 A**：落地星辉活世界 M1 → M2（已定稿方案执行） → 解决机会 #1
- 用户价值：TA/英雄离线也生活，回访有理由，聊天有谈资
- 商业价值：差异化护城河 + VIP/星晶消费新场景
- 最高风险假设：用户真的因"离线演化"提高回访（未验证）

**方向 B**：社交冷启动与分发补强（兴趣 onboarding + 推荐关注 + 搜索/Feed 个性化） → 解决机会 #2/#5
- 用户价值：新用户 10 分钟内找到同好、发出第一条被回应的动态
- 商业价值：拉高次留，扩大付费漏斗顶部
- 最高风险假设：个人开发带宽做得了推荐（可用规则/标签排序降级替代算法）

**方向 C**：关系沉淀与社交货币（Companion 关系里程碑 + 共同回忆册 + 成就合规分享出口） → 解决机会 #3/#4/#7
- 用户价值：关系有"进度条"，成就能被同好看见
- 商业价值：里程碑即付费点（纪念装扮/礼物）
- 最高风险假设：用户愿意把游戏成就分享到社交流（可能没人看反而尴尬）

## 我押

**方向 A** —— 理由：① 机会 #1 是唯一"重要性 H × 满足度 L"的象限；② 共享世界 + 异步英雄社交是竞品全部留白的位置，防御性最强；③ 方案已定稿且 M0/M1a 已落地，沉没成本低、路径清晰；④ 它同时验证总 PRD 的关键假设，结论直接决定 Companion 多 bond 与 M2 的开启。**方向 B 作为低成本并行补强**（规则版 onboarding + 推荐关注，不上算法），方向 C 等 A 验证后接入（里程碑天然是活世界事件的出口）。

## 关键假设

1. ⭐ 用户会因"TA/英雄离线也在生活"显著提高回访动机（⚠️ 合理推测，无验证 —— M1 即测试）
2. LLM 成本护栏（羁绊门槛 + ≤300 字 + 低频 tick + 快进摘要）足以让活世界单位经济成立（⚠️ 未压测真实成本）
3. 规则版 onboarding + 推荐关注足以改善冷启动，不需要真算法（✅ 有多数内容产品先例）
4. 用户会把英雄成就视为可分享内容而非隐私（❓ 纯直觉，C 方向启动前需验证）

## 压测结果

**判断**：⚠️ 有条件成立

**条件**：
- M1 必须按最小验证集执行（1 英雄 + 全屏营地 + 小家闲聊 + per-hero 记忆 + 快进摘要），验证指标不达标不启 M2
- 上线前必须实测 LLM 单次对话成本并回算 K3 护栏参数
- 方向 B 的 onboarding 只做规则版，禁止上推荐算法工程

**两个视角的综合**：
- 共同标记：活世界是最大的机会也是最大的成本/复杂度集中点——M1 范围必须死守最小集
- 核心张力：沉浸长文体验（O2）vs token 成本（K3）——用羁绊门槛把长文变成"奖励"而非默认，恰好两解
- 必答的一个问题：M1 验证指标的"达标线"具体数值是多少？（建议开工前写进 M1 任务卡，避免事后合理化）
