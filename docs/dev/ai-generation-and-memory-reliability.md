# AI 生成与记忆提取可靠性调整

## 背景

Companion 原先在聊天请求返回后启动无持久化的 goroutine 提取记忆。进程重启、模型超时或数据库暂时不可用时，这轮提取可能丢失；对话回复与提取任务也没有原子关系。Bot 发帖拒绝候选时，话题归档不应额外再调用一次本地模型，以免给小主机增加无意义的推理负载。

## 方案

### Companion 记忆提取

- 用户消息先写入 `companion_chat_logs`；完整成功回合的助手回复与提取任务在同一事务中创建。流式中断产生的部分回复保持现有行为，不排记忆任务。
- `companion_memory_extraction_jobs` 只保存用户、用户消息和助手消息的 ID，不重复保存聊天正文；每个用户消息最多关联一个任务。
- Companion 应用启动单进程串行 worker，领取到期任务后再读取聊天记录并调用已配置的推理服务。
- 任务使用运行租约和递增的 `attempt_count`；进程异常退出后，租约到期的任务可以重新领取，旧领取者不能覆盖新领取者的完成/重试状态。推理或记忆写入失败后按 15 秒起步、最多 30 分钟的指数退避重试，不因临时故障静默丢弃。
- 记忆写入复用现有来源记录、正文去重、稳定 `memory_key` 更新及用户确认冲突处理；任务重复执行不会再次创建相同来源的记忆。

### Bot 动态生成

- 生成候选统一经过重复正文、禁止标签、质量和语义重复检查；只有既有稳定度策略允许时，才从通过硬性检查的候选中放宽语义相似度。
- 创作方向轮换记录在运行日志中，下一轮从最近一次实际使用的方向继续。
- 被拒候选的话题归档使用规则分析，不再为每个失败候选额外调用模型。生成质量行为对本地和远程 Provider 一致，不增加 Provider 专属开关。

## 影响范围

- Companion biz/data、聊天与记忆模型、迁移注册及后台任务生命周期。
- `pkg/moe/runtime` 和 `pkg/moe/brain` 的 Bot 生成质检、运行日志与被拒内容归档。
- 不变更 Proto/API 契约，不修改 Flutter，不改 Feed/社交业务。
- 任务表只存关联 ID 和运行状态；推理客户端不回显上游响应正文，任务错误文本会截断，不把聊天正文复制进任务字段。

## 迁移步骤

1. 备份当前数据库，并部署包含 `companion_memory_extraction_jobs` 模型的后端版本。
2. 执行 `cd backend && make db-migrate`，确认新表和 `user_id + user_chat_log_id` 唯一索引已创建。
3. 重启单进程后端。新聊天回合应同时保存助手回复和 queued 任务；worker 会自动领取任务，无需额外配置或前端开关。
4. 通过数据库检查 queued/running/retrying/completed 状态；以 Companion 记忆列表验证成功提取。已有历史聊天不会自动补建任务。
5. 验证 Bot 试跑日志中的方向索引按轮次前进，并确认被拒候选路径没有额外的话题分析推理调用。

## 回滚方案

- 可回滚后端应用代码；新增任务表是增量表，回滚时保留，不手工删除。
- 回滚前优先等待 queued/running/retrying 任务清空。若仍有未完成任务，保留表与数据，恢复新版本后继续处理；旧版本不会消费这些任务。
- 本次不需要回滚 Proto、Flutter 客户端或现有记忆数据。
