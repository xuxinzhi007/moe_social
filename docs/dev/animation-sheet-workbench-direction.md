# 序列帧整理工作台方向

## 产品目标

把 AI 生成的杂乱角色动作帧，整理成一张可以直接交给任意 2D 游戏引擎使用的完整透明序列帧 Sheet。

用户不需要理解内部帧索引、Canvas 计算或资源命名，只需要完成：导入素材、整理动作、校准统一画布、导出 PNG。导出的 PNG 应能在 Godot 中通过网格裁剪直接使用，也能被其他引擎按统一 cell 尺寸读取。

## 当前错位

此前管理台同时存在两个方向：

- `AvatarComposerPage`：选择官方角色部件、组合角色、导出 avatar pack；
- `SpriteRepairPage`：导入散帧/视频/Sheet，整理帧池和动画行，导出 `spritesheet.png`。

用户真正需要的是第二个方向。当前入口已收敛为单一序列帧工作台，角色组合器不再作为该入口的并列模式；后续 avatar pack 生产属于独立内容资产域，不进入本工作台主流程。

`SpriteRepairPage` 作为当前工作台内核，已经具备帧池、动画行、逐帧变换、统一画布、视频抽帧、透明清理和 Sheet + JSON 导出等重要能力；后续开发必须围绕统一素材状态、导出契约和重导入验证推进。

## 目标工作流

```text
导入散帧 / Sheet + JSON / 视频
  → 统一帧池
  → 背景清理与透明检查
  → 全动作统一 cell 和角色原点
  → 动画行编排与时序调整
  → 最终 Sheet 预览
  → 导出 spritesheet.png + spritesheet.json
  → 重导入验证 / Godot 网格裁剪验证
```

## 明确不做

- 不把它做成 AI 人设生成器；
- 不把它做成服装槽位或官方角色包编辑器；
- 不把 Godot 私有配置混入通用 Sheet；
- 不把“能播放预览”当作“已经产出可用资源”；
- 不把每个导入、修复、预览、导出能力拆成互不相干的页面。

## 交付标准

第一阶段只验收一个完整闭环：使用真实 AI 生成的多动作素材，完成导入、帧整理、统一画布、透明 PNG Sheet 导出、JSON 重导入，并在 Godot 中按网格裁剪后正常播放。完成这个闭环后，再考虑音效、挂件、碰撞框或角色资产包等扩展能力。
