# 环境配置说明

## API 基址（Flutter App）

**唯一配置入口：** `lib/utils/config.dart` → `ApiEnvConfig`（`isProduction` / `developmentUrl` / `productionUrl`）。

> 类名原为 `AppConfig`，2026-09-08 改为 `ApiEnvConfig`：此前它与 `lib/config/app_config.dart` 的 `AppConfig`（第三方 LLM 密钥的安全存储，全是 async 方法）**同名不同物**，导入方要靠 `as moe_launch_config` 别名规避。现在两个类各叫各的，别名也去掉了。

`lib/services/api_service.dart` 在启动时通过 `ApiService.initBaseUrl()` 读取上述配置（纯本地同步，无网络请求），**不要**再在 `api_service.dart` 里硬编码 `_isProduction` 或 cpolar 地址。

```dart
// lib/utils/config.dart（当前实际值）
static const bool isProduction = false; // true = 线上；false = 本地
static const String productionUrl = 'http://47.106.175.49:8888';
static const String developmentUrl = 'http://192.168.124.36:8888'; // 开发机局域网 IP
```

| 模式 | 取哪个常量 | 说明 |
|------|----------|------|
| 本地开发（`isProduction = false`） | `developmentUrl` | 真机需填**电脑局域网 IP**；`127.0.0.1` 指向手机本机，连不上 |
| 线上（`isProduction = true`） | `productionUrl` | 真机 debug 也会走线上 |

**真机连本机后端：** 把 `developmentUrl` 改成电脑当前局域网 IP（`http://192.168.x.x:8888`），保持 `isProduction = false`。换网络/换机器就得改，改完**完整重启** App（Stop + Run），const 不参与热重载。

> Android 模拟器访问宿主机用 `http://10.0.2.2:8888`，iOS 模拟器可直接用 `127.0.0.1`。

**切环境的规则：** 手动改 `isProduction`，**不用**构建变量、CI 覆盖或启动时远程重写地址——见 `.cursor/skills/moe-flutter/SKILL.md` §1.9（勿提前强制 `kReleaseMode`）与 `docs/dev/app-usability-upgrade-plan.md` P0-A。

**发版把关：** `.github/workflows/flutter-release.yml` 在构建 APK 前有一步 `Assert release points at online API`，读到 `isProduction` 不是 `true` 就以 `::error::` 注解失败退出，并把本次发布用的两个基址打进构建日志。它**只检查、不覆盖**，所以「忘记切就发出去一个连开发机局域网地址的安装包」不会静默发生。配套的 `test/utils/config_test.dart` 另外拦住「切了 `true` 但 `productionUrl` 仍是内网/回环地址」——那种情况 CI 的 grep 看不出来。

穿透域名（cpolar / ngrok）若用于 `productionUrl`，`ApiService` 会自动附加隧道绕过头；隧道失效时请更新 `productionUrl`。

## 后端服务

| 服务 | 默认端口 | 说明 |
|------|----------|------|
| Kratos HTTP（唯一业务入口） | **8888** | `cd backend && make moe-social`；端口来自 `config.yaml` → `runtime.http_port` |
| Deploy Agent（按需） | **19010** | `cd backend && make deploy-agent`；`make moe-social` **不**自动启动它 |
| Ollama（n100 外部依赖） | **11434** | `llm_inference.base_url` = `http://192.168.124.77:11434`，见 [llm-inference-and-memory-vision.md](./llm-inference-and-memory-vision.md) |

> `make api` / `make rpc` / `make rpc-debug` / `make dev` 已随 go-zero 双进程一起删除，`backend/rpc/` 目录不存在；旧文档里的 `8080`（RPC）与 `6633`（`llm_inference.game_base_url` 占位）当前**无监听者**，详见 [ports.md](./ports.md#已无监听者的端口仅存在于配置代码残留)。

端口全表：[ports.md](./ports.md)。

后端监听与 CORS 见 `backend/config/config.yaml`（SSOT）；**无需**为前端切换而改后端端口。

## 管理台（moe-admin）

开发：`cd moe-admin && npm run dev` → http://127.0.0.1:5173/ops/  
Vite 将 `/api/admin` 代理到 `:8888`；运维菜单需另开 `make deploy-agent`（:19010）。

## 验证

1. Debug 控制台查看 `API环境: local/online` 日志（`ApiService` 启动时输出）。
2. 调用登录或任意 API，确认请求 host 与预期一致。
3. 管理台：登录后打开「推理状态」等页，确认能连上 API。
