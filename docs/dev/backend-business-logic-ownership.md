# Moe Social 后端业务归属与渐进迁移

## 背景

Moe Social 已完成 Kratos HTTP 服务迁移，生产请求由 `backend/cmd/moe-social` 提供；Flutter 仍是移动端界面与交互层。当前要解决的不是更换语言或重写应用，而是避免同一条业务规则在 Flutter、管理台和后端各维护一份，造成登录状态、跨设备数据、额度和状态判断不一致。

## 架构决策

**后端是业务规则与持久化状态的唯一权威来源；Flutter 与管理台是 API 消费者。** HTTP 契约继续以 `backend/api/<domain>/v1/*.proto` 为 SSOT，业务实现遵守 Kratos `protohttp → service → biz → data` 分层。

### 后端负责

- 身份、权限、数据所有权和跨用户隔离。
- 业务输入的最终校验、状态迁移、配额、保留期、可见性和排序规则。
- 社交、私信、AI 对话、记忆等需要跨设备或登录后恢复的数据。
- AI 提示词组装、模型调用策略、记忆提取与写入时机。
- 定时任务、Bot 行为、重试、幂等与失败后的状态处理。

### Flutter 与管理台负责

- 页面布局、动画、导航、无障碍与即时交互。
- 表单输入、键盘体验和不产生业务副作用的即时校验提示。
- ViewModel/Provider 编排域服务请求、加载/空/错状态、重试及乐观 UI。
- 本地草稿和缓存；它们可以改善体验，但不能成为跨设备业务记录的唯一副本。
- 将服务端错误转换成用户可理解的提示。客户端预校验不能替代服务端最终校验。

管理台可以编辑后端业务配置，但不能另行实现 Bot 配额、发布资格或模型调度等业务裁决。

## 不迁移的内容

- 纯展示逻辑、动画、页面导航和本地表单状态继续留在 Flutter。
- 草稿、离线缓存等体验数据可留在本地，但需明确其数据范围，并在服务端成功后对齐。
- 客户端即时校验可以保留，前提是最终规则由后端执行，且测试不把两份逻辑当成两个独立真相。
- 真正的实验性 UI 入口可以用 FeatureFlag；权限、配额和业务规则不能靠客户端开关保护。

## 分阶段迁移

每个域按同一顺序收口，不进行全仓一次性重写：

1. **盘点与定契约**：列出客户端决策、服务端已有能力、持久化位置、失败路径和旧客户端兼容要求；先确认 proto 与验收用例。
2. **服务端成为裁决点**：将权限、状态迁移、额度、幂等和持久化放入后端 biz/data；关键规则有服务端单测。
3. **客户端改为消费 API**：域 Service 负责协议转换，ViewModel 负责状态编排；UI 可做即时预校验，但以服务端响应为准。
4. **删除重复规则**：先由搜索与测试证明旧客户端规则不再决定结果，再删除重复业务代码；保留纯 UI 格式化和即时体验逻辑。
5. **端到端验收并更新状态**：验证登录态、跨设备/重启恢复、失败提示、重试、幂等和旧版客户端兼容；同步更新本文及域 SSOT。

### 推荐顺序

| 阶段 | 域 | 验收重点 |
|---|---|---|
| P0 | 聊天历史与 Companion 记忆 | 登录后恢复；每轮消息保存失败可见；记忆提取用持久任务、幂等重试，失败状态可观测 |
| P1 | Feed、发帖、评论、点赞、关注/好友 | 权限、重复提交、可见性和排序以服务端为准；客户端失败可回滚 |
| P2 | 私信与社区群组 | 多端历史、未读/已读、消息保留和离线送达保持一致 |
| P3 | Bot、Life、游戏与其他增强域 | 调度和状态归后端；Flutter 仅消费快照、事件和命令结果 |
| 持续 | 认证、钱包、VIP、礼物、管理端 | 资金、权限与资格判断禁止由客户端单独裁决 |

该顺序是审计与交付顺序，不代表未迁移域已经完成审计。每一域关闭前都要检查三栈（后端、Flutter、管理台）以及数据迁移/旧数据兼容。

## 失败与持久化约定

- 发送给用户的成功响应必须对应已完成的服务端持久化，或明确告知哪些记录未保存。
- 模型生成成功但记录保存失败时，尽量保留已生成内容，同时单独提示历史未保存；不可伪装成完整持久化成功。
- 异步记忆提取发生在聊天回复持久化之后，不阻塞正常回复；提取失败不能让聊天记录丢失，也不能让 UI 把“尚未提取”误认为“聊天未保存”。
- 记忆提取不能只依赖进程内 goroutine：任务需要持久化、可幂等重试并暴露最终状态，避免服务重启或模型失败后永久漏提取。
- 客户端本地数据回填、云端列表和缓存必须有清晰的数据所有权；不能通过静默吞错制造“已同步”的假象。
- 所有 API 变更先扩展 proto，保持兼容，再逐步移除客户端重复实现。

## 配额与调度约定

- `post_quota_daily = 0` 表示不限额，正数表示显式每日额度；负数非法。
- 配额只在发布成功后计入；外部发帖失败要释放预占额度。
- 智能发送不额外强加隐式每日额度或最小间隔。调度重试周期是减少重复推理的执行节奏，不等价于内容数量配额。
- 重复/相似内容检测、内容合法性和发布权限仍是内容质量与平台完整性规则，不因提高产量而删除。

## 迁移验收标准

- 一个业务事实只有一个服务端写入入口和一份后端裁决规则。
- 退出登录、换设备、重启 App 后，要求持久化的数据可从服务端恢复。
- 后端单测覆盖权限、边界、幂等、状态迁移及持久化失败；关键用户路径有 API 或集成验证。
- Flutter 域 Service/ViewModel 有请求成功、失败、重试和旧响应兼容验证；页面不直接承担业务裁决。
- 删除客户端重复规则前，已通过引用搜索确认只剩 UI 预校验、展示映射或必要的本地草稿逻辑。
- 验证按改动范围执行，避免为窄域迁移触发无关的全仓构建。

## 回滚方案

- API 采用增量兼容：先新增/扩展字段和后端行为，再发布客户端；暂不删除仍被旧客户端使用的字段或路由。
- 客户端回滚时保留已部署的后端接口和数据，不反向写入第二套业务真相。
- 数据迁移先备份并采用可重复执行的变更；未经明确计划不删除历史聊天、记忆或社交记录。
- 业务行为不通过客户端开关降级；如果需要暂停调度，应使用服务端运维控制并保留审计记录。

## 当前缺口

- 普通 AI 聊天历史的归属、删除后列表为空、跨账号隔离，由 `TestChatHistoryBelongsToActorAndDeletesCascade` 覆盖。换设备看到同一份历史，依赖这份服务端数据，不依赖本机库。
- 伙伴记忆提取失败时，用户还不能区分「聊天已保存」和「这段还没被记住」。
- 私信会话列表和未读只来自 `listPrivateConversations`。服务端列表为空就是空列表，不再用本机记录、通知或推送拼行。左滑隐藏仍只记在本机。好友未读读同一份列表。
- 世界书和模型来源名单只来自 `/api/ai/lorebooks`、`/api/ai/providers`。云端空列表不再回退本机 SQLite。Key 仍可下发到本机安全存储，供直连推理读取。
- 伙伴记忆提取连续失败达到上限后任务标为 failed，关系首页用 `memory_notice` 说明对话已保存但还有内容没被记住。
