# 用户级记忆统一改造验收脚本

> **架构 SSOT**：[用户记忆系统-OpenClaw式演进设计.md](./用户记忆系统-OpenClaw式演进设计.md)  
> **监控台**：[memory-system-dashboard.html](./memory-system-dashboard.html) · [docs/index.html](../index.html)

## 1. 目标

验证“后端用户记忆单一事实源 + Web 可用 + 模型切换不失忆 + raw 调试边界可见”是否真正落地；并覆盖 **混合检索** 与 **设备/记忆分离**。

## 2. 验收前准备

1. 使用同一账号登录 App/Web。  
2. 确认 `AI 模型配置` 页面里 `终端同款模式=已关闭`。  
3. 确认聊天接口显示为 `/api/llm/chat`。  
4. 选择一个模型 A（例如 `llama3:8b`）。  

## 3. E2E 脚本

### Case A：基础记忆命中

1. 在聊天中输入：`我叫小萌，我喜欢画画和爵士乐。`  
2. 再输入：`你记得我刚刚说了什么偏好吗？`  
3. 期望：回答中命中“画画/爵士乐”偏好，且语义正确。  

### Case B：模型切换后不失忆

1. 切换到模型 B。  
2. 输入：`你还记得我的爱好吗？`  
3. 期望：仍能命中同一用户偏好，不出现“重新认识你”的回答。  

### Case C：反馈后 1-2 轮生效

1. 打开 `模型记忆线`，找到相关记忆项。  
2. 对一条记忆执行 `correct`，例如把“爵士乐”改为“古典乐”。  
3. 返回聊天，输入：`我的音乐偏好是什么？`（连续 1-2 轮）  
4. 期望：回答逐步稳定为“古典乐”；旧偏好不再高频出现。  

### Case D：Web 端可用

1. 在 Web 端重复 Case A/B。  
2. 点击聊天页 `记忆库` 入口。  
3. 期望：可进入后端记忆线页面并看到同账号记忆。  

### Case D2：聊天页不走本地记忆链路

1. 在移动端与 Web 端分别发起同主题对话。  
2. 确认两端回答都依赖同一账号记忆，不因本地 SQLite 差异出现不同“人设”。  
3. 期望：聊天页仅依赖后端记忆注入链路，本地记忆变化不影响主聊天行为。  

### Case E：raw 调试边界

1. 开启 `raw 调试模式`。  
2. 聊天一轮后观察回答（允许出现记忆不命中）。  
3. 打开 `AI 模型配置` 页，确认显示 `服务端记忆是否生效=否（raw 调试）`。  
4. 关闭 raw 模式后再测一轮，期望恢复服务端记忆命中。  

### Case F：桥接异常可提示

1. 人为让后端无法连接 Ollama（例如停掉本地 Ollama）。  
2. 发起聊天或点击连接测试。  
3. 期望：前端出现明确错误提示，不是静默失败。  

### Case G：混合检索（Phase 2）

1. 聊天或 `POST /memories` 写入一条事实，例如 key=`hobby`，value=`喜欢手冲咖啡`。  
2. 调用 `POST /api/user/:id/memories/reindex`（或监控台「POST reindex」），期望 `indexed >= 1` 且返回 `provider`/`model`。  
3. 调用 `GET /api/user/:id/memories/search?q=咖啡爱好`（与原文用词不同），期望命中 `hobby`。  
4. 关闭 `memory.search.hybrid_enabled` 后仅关键词仍可命中含「咖啡」的原文。  

### Case H：设备与记忆分离

1. `GET /api/user/:id/memories` 列表中不应出现 `device_info:*` 作为用户记忆展示项。  
2. `GET /api/user/:id/devices` 可返回当前账号设备登记。  
3. `POST /memories` 且 `source=device_sync` 应被拒绝。  

### Case I：记忆工具 list 过滤（路径 B，可选）

1. Provider 开启「支持 tool_calls」。  
2. 模型调用 `memory_list`，参数 `query=咖啡`，期望返回与 search 相近的子集。  

## 4. 指标口径（观察期）

### 4.1 记忆命中率

- 定义：命中记忆的回答轮次 / 总回答轮次。  
- 建议窗口：按用户近 50 轮统计。  

### 4.2 误提率

- 定义：被用户 reject/correct 的记忆条数 / 新提取记忆条数。  

### 4.3 冲突率

- 定义：同一 `user_id + key` 在 24h 内发生值冲突的比例。  

### 4.4 反馈采纳率

- 定义：反馈后 1-2 轮内回答行为变化达成的比例。  
- 判定：可由人工抽样或规则匹配（关键词命中）评估。  

### 4.5 注入 token 成本

- 定义：记忆注入文本估算 token / 轮。  
- 目标：在命中率提升前提下，保持成本稳定或下降。  

## 5. 通过标准

1. Case A/B/C/D/E/F 全部通过。  
2. 反馈采纳率达到可用阈值（建议 >= 70%）。  
3. 命中率提升趋势明显，误提率可控且逐周下降。  

## 6. 当前已知待收敛项

1. `MemoryManagerPage` 仍保留本地 SQLite 画像/配置链路，需要迁移到后端来源。  
2. 大用户记忆列表仍建议补充分页/limit 与后端查询观测。
