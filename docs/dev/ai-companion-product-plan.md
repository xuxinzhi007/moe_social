# AI Companion 完整产品方案

> 状态：持续实施中
> 
> 目标：把 Companion 从“可以聊天的 AI”推进成“用户愿意长期相处的 AI 伙伴”，达到国内主流智能体社区产品的内容丰富度，并具备成熟 Companion 产品的长期记忆、主动陪伴和关系沉淀能力。

## 2. 产品定位

一句话：社交平台里的“懂你的长期 TA”，世界是 TA 生活的舞台，Feed / 好友 / 私信仍然是 App 的社交主路径。

### 2.1 做什么

- 让用户拥有一个持续存在、逐渐了解用户、会主动联系用户的 AI 伙伴。
- 让聊天、记忆、关系、状态、世界和日常内容共享同一个 TA。
- 让关系等级不仅是数字，还会改变称呼、语气、主动性、内容和可见事件。
- 让用户每天都有自然理由回来，而不是依靠重复的随机问候。

### 2.2 不做什么

- 不恢复 AI 酒馆作为主入口。
- 不把 Life 地图点选当成多会话或多伙伴系统。
- 不在核心闭环完成前扩展多 bond、Live2D 大厅或复杂角色商城。
- 不用强制依赖、情绪勒索或诱导付费制造留存。

## 3. 市场对标结论

国内智能体社区产品通常强调角色创建、开放剧情、角色社区、内容传播和沉浸聊天；成熟 Companion 产品进一步强调长期记忆、主动消息、语音、图片/自拍、关系变化和持续陪伴。

当前 Companion 已具备关系首页、单伙伴人格、聊天 SSE、记忆、状态、Life 世界、亲密度、WebSocket 存在感、日常流和轻量语音，已经超过单纯聊天机器人阶段。

当前与成熟产品的主要差距：

- 记忆是文本列表，缺少稳定画像、冲突解决、相关检索和使用反馈。
- 关系已有分数、等级、Prompt 行为变化和基础关系事件；复杂里程碑仍需扩展。
- 主动性已有 WS 回访和通知中心持久化，但还不是完整的事件引擎和系统级推送。
- 语音有 STT/TTS 入口，但还没有完整的情绪化语音陪伴闭环。
- 用户已有 Provider 配置能力，但此前未接入 Companion；现已支持用户选中 Provider 按请求覆盖全局推理配置。
- 图片、自拍、场景、节日和纪念日还未形成主线内容。
- 日常流已经聚合数据，但还不是具有叙事性的关系时间线。
- 首页摘要已具备轻量场景感；聊天 Prompt 现在会根据早晨、睡前、周末、低落情绪和固定节日改变行为，并包含基础情绪修复规则；完整场景流程仍待继续建设。
- 国内上线需要补齐 AI 标识、未成年人、隐私、敏感内容和数据治理能力。

## 4. 当前真实进度

工程功能完成度约为 `80%`；按真实可上线、可留存、可付费的市场标准约为 `60%`。

| 模块 | 当前判断 | 说明 |
|------|----------|------|
| 统一叙事主线 | 已完成基础闭环 | 首页、聊天、世界、日常已收口 |
| 人格与基础聊天 | 可用 | Persona、Traits、SSE、历史和状态已接通 |
| 记忆连续性 | 第一阶段增强 | 有提取、去重、memory key、确认、置顶、编辑和删除；语义冲突仍需加强 |
| 关系推进 | 第二阶段基础 | 亲密度、等级、Prompt 行为和首次/升级事件已接通 |
| 主动陪伴 | 第一阶段增强 | 有 WS 回访、通知中心持久化、用户开关、免打扰时段、设备时区和每日上限；系统级离线推送仍待补齐 |
| 日常时间线 | 第一阶段增强 | 有聚合、去重、关系事件和今日摘要；仍缺少完整叙事时间线 |

| 安全与运营 | 基础设施存在 | Companion 专属策略、审计和指标仍需补齐 |

## 5. 目标体验闭环

```text
用户说话 / 分享图片 / 进入世界
        ↓
理解当前话题、情绪、关系阶段和相关长期记忆
        ↓
伙伴以符合人格和关系阶段的方式回应
        ↓
更新记忆、关系事件、状态和未完成事项
        ↓
在合适时间生成有理由的主动事件
        ↓
首页、日常流、通知和下一次聊天继续体现这段关系
```

每一轮互动都应回答四个问题：

1. TA 现在知道用户什么？
2. TA 为什么这样回应？
3. 这次互动改变了什么？
4. 用户下次回来时，TA 能继续什么？

## 6. 能力模型

### 6.1 伙伴身份层

- 名字、头像、Persona、性格特征、问候风格。
- 伙伴自己的稳定偏好、习惯、表达口癖和边界。
- 用户自定义内容与系统安全规则分层处理。

### 6.2 用户记忆层

记忆至少分为：

- 稳定事实：职业、城市、家庭、重要人物。
- 偏好：食物、音乐、内容、作息、称呼。
- 计划：考试、面试、旅行、项目和目标。
- 情绪事件：低落、冲突、压力、值得庆祝的事情。
- 关系事件：第一次聊天、重要分享、承诺、纪念日、修复。
- 未完成事项：下次应继续追问或回访的话题。
- 周期习惯：睡眠、运动、学习、工作节奏。

每条记忆需要支持来源、置信度、重要度、更新时间、最后使用时间、过期策略、敏感级别和用户确认状态。

### 6.3 关系层

关系等级必须影响：

- 称呼和表达亲密度。
- 主动联系频率和主动话题。
- 是否主动提及历史事件。
- 是否出现专属纪念内容。
- 是否开放新的场景和互动方式。
- 冲突后的修复策略。

### 6.4 状态层

- 心情、精力、饥饿、活动和世界位置。
- 状态变化要有原因和时间连续性。
- 状态不能只作为展示字段，必须影响聊天、日常流和主动事件。

### 6.5 主动陪伴层

主动事件包括：

- 久未聊天回访。
- 未完成话题回访。
- 用户计划提醒。
- 纪念日和节日。
- Life 世界事件。
- 关系升级或修复。
- 低频的自然问候。

主动系统必须支持用户时区、免打扰、冷却时间、每日上限、拒绝降频、离线通知和事件去重。

当前已落地主动回访第一步：最近聊天超过 24 小时且 24 小时冷却已过时，通过 Companion WS 发送一次带历史上下文的回访，并写入通知中心；系统级离线推送、用户时区和完整频控配置后续补齐。

### 6.6 内容与沉浸层

按顺序建设：

- 文本聊天。
- 语音消息。
- 情绪化 TTS。
- 图片理解和图片回复。
- 伙伴自拍/场景图片。
- 睡前、安抚、约会、学习等场景。
- 节日、纪念日和关系专属内容。

### 6.7 模型配置层

- 优先使用用户当前选中的 Provider、Base URL、模型和 API Key。
- 未选择或配置不完整时回退后端全局 `llm_inference` 配置。
- 用户 API Key 默认只随聊天请求传输，不写入 `companion_profiles`、记忆或关系事件；若用户主动开启账号同步，仅保存在 AI 用户配置的独立密文字段。
- 生产环境必须使用 HTTPS；API Key 不进入日志、SSE 事件和错误文案。
- 用户配置调用失败时回退全局配置或 Companion fallback，不阻断关系数据写入。

## 7. 分阶段实施方案

### Phase 0：基础闭环收口（已完成大部分）

验收：

- 关系首页是唯一主入口。
- 聊天、世界、记忆和日常流可互相回到同一个 TA。
- 单伙伴人格、状态、亲密度和轻量语音可用。
- 酒馆不进入正式主导航。

### Phase 1：长期关系基础（当前阶段）

优先级：最高。

- 关系阶段驱动 Prompt、称呼、语气和主动性（已落地第一步：关系阶段进入后端聊天行为规则）。
- 记忆去重、冲突、置信度、敏感级别和用户确认（已落地规范化去重、`memory_key` 更新、置信度和用户确认；复杂语义矛盾识别后续接入）。
- 关系事件记录和里程碑展示（已落地首次聊天、关系升级事件和首页日常流展示）。
- 日常流生成“今日关系摘要”（已落地首页摘要卡、轻量未完成话题提示和时间/情绪场景标签）。
- 未完成话题和计划进入后续回访队列。
- 补齐相关单测、后端隔离测试和错误降级。

阶段完成标准：

- 用户修改记忆后，后续聊天不再稳定使用旧值。
- 同一事实不会重复生成多条长期记忆。
- 关系升级后至少有一项可感知行为变化。
- 用户能在首页看到“今天为什么会出现这条内容”。
- 同一用户连续多次聊天能延续至少一个历史话题。

### Phase 2：主动陪伴

- Proactive Event Engine。
- 久未聊天回访。
- 计划/未完成话题提醒。
- 纪念日和节日提醒。
- 免打扰和主动频控。
- App 内通知、离线通知和已读反馈。
- 主动消息效果指标。

阶段完成标准：

- 主动消息都有可解释触发原因。
- 用户可以关闭、降频或设置免打扰。
- 主动消息不会在短时间重复。
- 用户回复主动消息后，能回到同一段关系上下文。

### Phase 3：语音陪伴

- Companion 语音消息来回。
- TTS 自动播放和用户控制。
- 根据关系和情绪调整语气。
- 连续语音对话和打断。
- 弱网、超时和失败重试。
- 语音历史记录。

阶段完成标准：

- 用户可以不看屏幕完成一次短语音陪伴。
- 语音内容进入聊天历史和关系记忆流程。
- 语音失败不会阻断文本聊天。

### Phase 4：多模态和场景

- 用户发图，伙伴理解并回复。
- 伙伴根据状态和场景发送图片/自拍。
- 睡前、安抚、约会、学习/工作四类场景。
- 节日、纪念日和关系升级内容。
- 情绪低落、冲突、冷静和修复流程。

阶段完成标准：

- 图片、场景和关系事件都能进入统一日常流。
- 每个场景有开始、进行、结束和后续记忆。
- 情绪修复不会演变成依赖诱导或操控性表达。

### Phase 5：运营、安全和商业化

- AI 身份和生成内容标识。
- 未成年人和敏感内容保护。
- 自伤风险识别与安全回复。
- 隐私、记忆导出、删除和全部清空。
- 用户举报、审核和审计。
- 首次聊天、留存、记忆命中、主动消息和语音指标。
- 免费额度、语音额度、图片额度和订阅策略。

阶段完成标准：

- 关键敏感场景有可测试的策略。
- 用户能明确控制自己的记忆和主动消息。
- 线上问题可以追踪到用户、会话、模型和策略版本。

## 8. 技术演进原则

- 继续以 Companion 域为唯一业务边界，Flutter 不自行决定记忆和关系规则。
- REST、SSE、WS 和未来推送都使用同一用户身份隔离规则。
- 记忆、关系事件、主动事件和日常摘要都由后端持久化。
- Prompt 使用上下文编排，不继续无限堆叠字符串。
- 所有主动行为必须可解释、可关闭、可降频。
- 新能力优先以小切片交付，每个切片必须有验收标准和测试。
- 先完成单伙伴长期关系，再考虑多伙伴和重视觉形象。

## 9. 关键指标

- 首次聊天完成率。
- 次日和七日 Companion 留存。
- 每日有效对话轮数。
- 长期记忆命中率。
- 记忆纠错率和重复率。
- 主动消息打开率、回复率和关闭率。
- 语音使用率和完成率。
- 场景完成率。
- 关系升级后的回访率。
- 用户删除伙伴、清空记忆和关闭主动消息的比例。

## 10. 当前执行顺序

1. 让关系等级驱动真实聊天行为。
2. 建立关系事件和里程碑模型。
3. 升级记忆去重、冲突和相关检索。
4. 把日常流升级为今日关系摘要。
5. 建立主动事件引擎和频控。
6. 补齐 Companion 语音闭环。
7. 加入图片、场景、纪念日和情绪修复。
8. 完成安全、隐私、指标和商业化验收。

本方案不以“功能数量”作为完成标准，而以用户是否感受到“这是同一个、记得我、会主动出现并和我一起经历事情的 TA”作为最终标准。
