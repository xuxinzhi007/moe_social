# Ollama 用户级记忆统一文档

## 1. 文档定位

本文件是当前项目 **Ollama 用户级记忆** 的单一入口（SSOT 文档入口）。

目标：

1. 把“缺陷分析、架构设计、实施状态、验收路径”集中在一处。  
2. 降低文档分散导致的信息不一致问题。  
3. 让开发、联调、验收都能按同一份口径执行。  

---

## 2. 现状结论（截至 2026-05-09）

1. 聊天主链路已统一走后端记忆链路（`/api/llm/chat`）。  
2. `raw` 模式定位为调试模式，不作为默认用户路径。  
3. 用户记忆以后端账号维度存储（`users.id` 绑定），支持跨端复用。  
4. 记忆字段与反馈链路已落地：`memory_type/confidence/source/source_msg_id/session_id`。  
5. 前端记忆线与管理页已主要切换到后端来源；剩余收敛项仍在推进。  

---

## 3. 核心目标

1. **连续性**：同一用户跨天、跨设备“被持续记住”。  
2. **可治理**：记忆可查看、可纠错、可删除、可追溯。  
3. **可学习**：反馈能驱动强化/衰减，形成持续优化闭环。  
4. **可控成本**：记忆注入按相关性和预算控制，避免 token 失控。  

---

## 4. 统一架构原则

1. 后端记忆系统是单一事实源（SSOT）。  
2. 前端不再做“主链路记忆推断与注入”，只做展示与反馈交互。  
3. `raw` 模式仅用于调试与问题定位，不承诺记忆命中。  
4. 冲突处理遵循：**用户定义 > 用户反馈 > 模型抽取**。  

---

## 5. 当前能力盘点

### 5.1 已完成

1. 记忆召回：相关性 + 最近性 + 注入预算。  
2. 记忆治理：去重、噪声过滤、敏感日志收敛。  
3. 反馈闭环 V0：`accept/reject/correct`。  
4. 账号级缓存：按 `user_id` 短 TTL 缓存 + 更新失效。  
5. 画像聚合：后端聚合接口 + 缓存表读写策略。  
6. 记忆列表分页：`limit/offset + total/has_more`。  

### 5.2 进行中

1. 反馈驱动强化/衰减离线任务（批处理、阈值策略）。  
2. 画像聚合纯离线定时全量任务补强。  

---

## 6. 关键接口（当前口径）

1. `POST /api/llm/chat`：主聊天链路（服务端记忆注入）。  
2. `POST /api/llm/chat/raw`：调试转发链路（默认不走）。  
3. `GET /api/user/:user_id/memories`：记忆列表（分页）。  
4. `POST /api/user/:user_id/memories`：新增/更新记忆。  
5. `DELETE /api/user/:user_id/memories`：按 key 删除。  
6. `POST /api/user/:user_id/memories/feedback`：反馈与纠错。  
7. `GET /api/user/:user_id/memories/profiles`：后端画像聚合。  

---

## 7. 性能与稳定性口径

1. 读路径：缓存优先，DB 为回源。  
2. 注入路径：相关召回 + 上限控制，不全量塞入 prompt。  
3. 写路径：更新后失效缓存，保证一致性。  
4. 观测口径：慢查询耗时、分页参数、返回条数、聚合重建触发。
