# AI 伙伴推进路线

> 目标：按 `Replika / Nomi` 的产品方向，把现有 Companion 从“能聊”推进到“更像长期关系”。

> 进度口径：以下百分比按「正式上线 Companion」的必需能力计算，不按单个功能是否写完计算。
> 以后每次推进完，我都按这份口径回报当前总进度。

## 现状

- 已有：`profile / state / memory / chat history / SSE / WS / intimacy / 语音 STT-TTS / 日常流`
- 已有 UI：关系首页、聊天页、记忆页、资料编辑、实时存在感
- 当前短板：记忆连续感、主动性、关系推进、语音沉浸、内容丰富度

## 正式上线口径

Companion 要算“正式上线”，至少要满足：

- 关系首页是唯一主入口叙事，不是酒馆大厅
- 聊天是统一主线，能持续记住用户和关系状态
- 日常流能把聊天、记忆、状态、世界动态串成同一条时间线
- 伙伴可见成长：关系等级、亲密度、阶段文案
- 伙伴会主动出现：问候、提醒、久未聊天回访
- 语音是陪伴的一部分，不是附属工具
- 资料 / 记忆 / 世界 / 聊天共享同一个 TA，而不是多套人格拼接

## 进度算法

| 模块 | 权重 | 说明 |
|------|------|------|
| 统一叙事主线 | 20% | Companion 只有一条体验主线，入口和文案一致 |
| 记忆与状态连续性 | 25% | 记忆注入、状态同步、日常流、历史回看 |
| 关系推进 | 20% | 亲密度、等级、阶段、里程碑 |
| 主动陪伴 | 15% | WS/推送/回访/久未聊天问候 |
| 语音沉浸 | 10% | STT/TTS、语音消息、通话 |
| 内容表现与细节 | 10% | 场景、节日、图片、情绪修复 |

当前总进度 = 各模块已完成度 × 权重之和。

## 里程碑

- `40%`：基础陪伴可用，能稳定聊天 + 有关系首页
- `60%`：有记忆连续感和关系进度，像“同一个 TA”
- `80%`：能主动出现、能语音、日常有时间线闭环
- `100%`：接近正式上线体验，补齐场景、节日、图片与情绪修复

## Phase 1

- 更强记忆感：把关键偏好、事件、纪念点注入到聊天和首页
- 关系进度：增加阶段文案、关系里程碑、可见成长曲线
- 主动消息：支持久未聊天后的问候、事件触发提醒
- 语音消息 / 通话：补齐 Companion 的语音来回能力
- 日常事件流：把状态、记忆、聊天高光统一成可追溯时间线

## Phase 2

- 自拍 / 图片回复：让 TA 能“看见并回应”图片
- 场景模式：约会、安抚、日常、睡前、学习陪伴
- 节日 / 纪念日：固定仪式感内容和专属消息
- 情绪波动与修复：低落、吃醋、冷静、哄回来的循环

## Phase 3

- 多角色 / 多 bond：如果产品决策要扩展，再在 Companion 域演进
- 更强沉浸表现：仅在明确需要时再考虑更重的视觉方案

## 推荐顺序

1. 先补记忆和关系进度
2. 再做主动消息和语音
3. 再做图片、场景和节日

## 落地原则

- 不回到酒馆大厅
- 不把 Life 地图点选误当成多会话
- 先强化单个主伙伴体验，再谈多角色
