# 本地开发包与正式包隔离维护说明

## 1. 目标

降低本地调试时 debug 包与正式包冲突带来的安装切换成本，且不影响线上正式发版。

---

## 2. 本轮已完成（仅 1、2）

1. Android `debug` 构建增加包名后缀：`.dev`。  
   - 位置：`android/app/build.gradle.kts`
2. Android `debug` 应用名称改为 `Moe Social Dev`。  
   - 位置：`android/app/src/debug/res/values/strings.xml`
3. 正式包名称保持 `Moe Social`。  
   - 位置：`android/app/src/main/res/values/strings.xml`

备注：线上正式环境配置未调整，release 仍按原包名与原签名发布。

---

## 3. 后续待做（本轮未改动，留档维护）

1. **图标区分（可选）**  
   - 为 debug 增加 `Dev` 角标图标，降低桌面误点概率。
2. **更新源隔离（建议）**  
   - debug 包默认禁用正式更新，或接入独立 dev 更新源。
3. **设置页可见性增强（建议）**  
   - 展示：当前包名、构建类型（debug/release）、更新地址。
4. **iOS 本地开发包隔离（可选）**  
   - 若需 iOS 也共存，后续再加 debug bundle id 后缀。

---

## 4. 使用建议

1. 本地开发安装 `debug` 包（`Moe Social Dev`）。  
2. 日常使用保留正式包（`Moe Social`）。  
3. 两者可并存，避免反复卸载安装。

---

## 5. CI 打包配置建议（GitHub Actions）

当前仓库 workflow 使用 `flutter build apk --release`，不会受本次 debug 包名后缀改动影响。  

建议新增一条“产物存在性校验”步骤，避免后续路径调整时静默失败：

1. 构建后执行：`ls -lah build/app/outputs/flutter-apk/`。  
2. 严格校验：`test -f build/app/outputs/flutter-apk/app-release.apk`。  

若未来需要在 CI 同时产出开发包，再额外增加 debug 产物流程（例如 `flutter build apk --debug` 并上传 `app-debug.apk`）。
