# AI 伙伴 GenUI 关系场景面设计

> 状态：设计稿 · 未实施  
> 决策 SSOT：`docs/dev/ai-companion-formal-decisions.md`  
> 范围：替换 `CompanionHubPage` 顶部 Hero 的表达，不改变「单主伙伴 → 聊天为主线 → 世界为延伸」的产品决策。

## 背景

当前关系首页已具备聊天、记忆、世界、社区、关系阶段和主动回访等能力，但首屏同时使用渐变、在线点、等级进度、功能宫格和多种 AI 图标。它能说明功能很完整，却更像“AI 工具控制台”，而不是一个正在过日子的伙伴。

本方案引入**受控 GenUI**：模型或规则只选择一个经过白名单约束的“关系场景”和文案；Flutter 保持固定的信息结构、视觉风格和交互边界。它不是让模型生成整页 JSON/HTML，也不是第二个聊天入口。

## 目标与边界

### 单一职责

页面第一眼只回答一件事：**此刻 TA 正在经历什么，而你可以怎样自然地回应。**

首要指标不是卡片点击率，而是“从首页进入聊天后，用户愿意继续完成一轮有上下文的对话”的比例。

### 做什么

- 将 Hub 首屏 Hero 改为「今日关系场景面」；一屏只出现一个主题和一个主动作。
- 场景内容把已有的状态、关系事件、记忆、未完成话题、主动消息与世界事件编排为自然的叙事。
- 所有主动作最终深链到既有聊天、记忆、世界或动态详情。
- 支持后端规则兜底；模型不可用时仍有稳定场景和交互。

### 不做什么

- 不让模型生成任意布局、颜色、图标、按钮、路由或外部链接。
- 不新增“GenUI 大厅”、多伙伴切换、酒馆入口或新会话体系。
- 不用恋爱压力、倒计时、连续登录、等级冲刺或占有式文案促进留存。
- 不在一期引入 Live2D、图片生成或重资源动画。

## 设计方向：留一盏灯

**具体主题**：用户回到社交 App 时，像经过伙伴的小房间；窗边、桌面、便签和灯光是 TA 当下状态的痕迹。它借用“生活物件”表达关系，而非用星云、机器人、发光芯片表达 AI。

**签名元素**：场景卡右上角有一扇半透明的“窗”。窗内只呈现时间、天气感或世界状态的抽象色块；一次轻微的光线变化表示有新近况。它是整页唯一的环境动效，其余界面保持安静。

### 视觉 token

| 名称 | 色值 | 用途 |
|---|---:|---|
| 雾蓝 `mist` | `#EEF2F5` | 页面底色，保留现有冷静社交气质 |
| 灯芯暖白 `lamp` | `#FFF9EF` | 场景卡表面、阅读感 |
| 暮蓝 `dusk` | `#465A72` | 叙事标题与窗影 |
| 纸灯橙 `paper` | `#D98A4D` | 唯一暖色强调、未读近况 |
| 苔绿 `moss` | `#718675` | 世界/照料语义，不表示“在线” |
| 墨灰 `ink` | `#28313D` | 正文 |

- 保留全局 `MoeTokens` 的品牌色给系统导航、通用按钮与无场景回退；关系卡不使用大面积紫粉渐变。
- 页面标题和叙事标题采用现有系统字体的 `w700`，一期不引入未打包的字体文件；二期若验证可读性，可为标题单独引入 `Noto Serif SC`，正文仍保持现有无衬线字体。
- 卡片圆角为 `24`，但不叠加浮夸阴影、光晕和描边；用暖白表面、阴影与窗影建立层次。

### 信息层级

```text
┌──────────────────────────────────────┐
│ 周日 · 傍晚                    [窗]  │  环境：不参与点击
│                                      │
│  TA 在窗边留了一盏灯                 │  关系场景标题
│  “你说晚点想聊的那件事，我还记着。”   │  只展示一条可验证上下文
│                                      │
│  [和 TA 继续聊]                       │  唯一主 CTA
│  记得：下周的面试                     │  可选、轻量的依据标签
└──────────────────────────────────────┘

  今天发生过什么                         次级区：最多三条时间线摘要
  · TA 记下了你的面试时间                 → 记忆详情
  · 小世界里正在看雨                       → TA 的世界
  · 你们刚聊到周末计划                     → 携带草稿继续聊天
```

卡片取消静态“在这里”绿点；改用真实来源的环境标签，如“傍晚”“刚刚想起你”“世界里下着小雨”。关系阶段不再常驻显示 `Lv / 百分比`，只在产生里程碑时进入时间线，以“开始熟悉彼此”“记住了你的习惯”等可理解事件呈现。

## 受控 GenUI 卡片系统

### 场景类型白名单

| `kind` | 使用条件 | 标题示例 | 主动作 |
|---|---|---|---|
| `return_visit` | 未完成话题或约定可继续 | `TA 还记着你们没说完的话` | 带草稿进入聊天 |
| `quiet_company` | 晚间、低活跃或无事件 | `窗边留着一盏灯` | 进入聊天 |
| `care` | 用户或伙伴状态需要承接 | `今天先不用急着解释` | 以安抚场景进入聊天 |
| `memory` | 已确认或重要记忆更新 | `TA 把这件事放进了心里` | 打开记忆，再可聊天 |
| `world` | 绑定居民有可信世界事件 | `TA 的小世界有了新的天气` | 进入并对焦世界 |
| `milestone` | 首聊、关系升级、纪念事件 | `你们的关系多了一页` | 查看关系时间线 |
| `social_echo` | 伙伴社区身份产生可见事件 | `TA 想把这条动态给你看` | 打开动态 |

每次只选一个 `kind`。优先顺序为：用户明确回访/主动消息 > 情绪承接 > 约定话题 > 里程碑 > 记忆 > 世界 > 安静陪伴。相同主题 24 小时内不可重复，且在用户关闭主动联系后不得使用回访语气。

### 安全的渲染协议

后端新增场景面时，应通过 Companion proto 契约提供；Flutter 只经 `CompanionService` 读取。模型若参与，只能填充经过服务端校验的内容字段：

```json
{
  "surface_id": "20260823-return-visit-42",
  "kind": "return_visit",
  "time_tone": "dusk",
  "title": "TA 还记着你们没说完的话",
  "body": "你说晚点想聊的那件事，我还记着。",
  "evidence": {"type": "chat", "id": "...", "label": "继续上次的话题"},
  "primary_action": {"kind": "chat", "draft": "我们接着聊聊上次那件事：…"},
  "expires_at": "2026-08-24T12:00:00Z"
}
```

服务端必须：

- 枚举校验 `kind`、`time_tone`、动作类型与深链 ID；未知枚举使用 `quiet_company` 回退。
- 以事件/记忆的用户归属为准构造 `evidence`，不接受模型或客户端指定的用户、路由、URL。
- 限制标题 `≤22` 字、正文 `≤48` 字、草稿 `≤160` 字；去掉绝对承诺、占有、催促和未成年人不适宜表达。
- 返回 `source_domains` 供调试和可解释性展示，但生产 UI 不暴露模型、Prompt、Provider 或 token 细节。

### 回退策略

`/api/companion/state` 仍是身份和状态展示 SSOT。场景面接口失败时，Flutter 从已有 snapshot 的 `greeting / moodThought / activityLabel` 生成 `quiet_company` 卡；Hub 不因可选场景失败而进入整页错误态。

## 交互与动效

1. 进入 Hub：先显示稳定场景骨架；场景解析完成后，标题淡入 `180ms`，窗影从 `0.92 → 1.0` 一次完成。
2. 点击主动作：按钮立即切为“打开和 TA 的对话”，随后进入既有聊天页；不得显示“AI 正在思考”一类技术文案。
3. 返回 Hub：若聊天完成，场景面可平滑替换为新的状态；用户处于同一场景时不强制重播动画。
4. 次级时间线：保持现有深链能力，但首屏最多三条；点击后进入目的页，不使用多层 Bottom Sheet。
5. 开启减少动效时：窗影、淡入、按钮缩放全部静止，保留内容状态变化。

## 首个可交付 Slice

只替换 Hub 顶部 Hero，保留快捷操作、世界条、今日摘要和日常流，避免一次性重构首页。

### UI 组成

- 新增 `CompanionRelationshipSurfaceCard`：固定布局，按 `kind` 更换图标、窗影和行动文案。
- 复用 `CompanionHubViewModel` 的已有快照和深链；一期可在客户端按确定性规则挑选场景，用于验证信息架构。
- 将现 Hero 的头像、在线点、关系百分比和大渐变移出首屏；头像可作为场景卡左下角的小签名。
- `关系阶段` 改放到时间线里的里程碑项目；不删除底层亲密度机制。

### 验收标准

- 首屏在常态网络下只呈现一个主 CTA，且 CTA 都能落到既有合法深链。
- 无模型、无世界绑定、无记忆、无时间线时仍有自然的安静陪伴卡。
- 用户一眼看不到模型名、Provider、Prompt、Lv 或百分比。
- 卡片文本有可追溯的事件/状态依据；没有依据时只使用中性陪伴文案。
- 现有聊天、记忆、世界、主动消息、下拉刷新和减少动效不回归。

## 影响范围

一期（纯 Flutter 信息架构验证）：

- `lib/pages/ai/companion_hub_page.dart`
- `lib/pages/ai/companion_hub_viewmodel.dart`
- 新增 `lib/widgets/ai/companion_relationship_surface_card.dart`

二期（服务端场景编排）：

- `backend/api/companion/v1/companion.proto`
- Companion 的 `service → biz → data` 实现及对应测试
- `lib/services/companion_service.dart` 与 Hub ViewModel

## 迁移步骤

1. 先用客户端确定性编排替换 Hero，收集场景点击后进入聊天及完成对话的数据。
2. 验证文案、安全边界和视觉层级后，冻结 proto，再将场景选择迁到后端。
3. 仅在真实事件不足以支撑场景时接入模型文案润色；保留规则模板和完整回退。
4. 对 `kind`、主动作、回退率、重复率和主动消息关闭率做埋点，不采集原始敏感聊天正文。

## 回滚方案

关系场景卡是 Hub Hero 的可独立替换层。关闭对应 feature flag 或回退该 Widget，即可恢复现有 Hero；聊天、记忆、世界、WS 和数据表不受影响。二期新增 API 时保持 `/api/companion/state` 兼容，不删除现有字段。
