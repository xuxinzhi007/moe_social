关系稿 · 身份

用户、伙伴、居民，不是同一行。

社交图里的好友，和世界里两个居民的关系，用的不是一张表。伙伴可以记下某个居民的编号，头像仍然分开。字段见 relationships.md。

社交 · user
Userusername、moe_no、email 唯一
Post · Comment · Like内容挂在用户上。点赞指向帖或评论
Follow关注者指向被关注者，一对唯一
FriendRequestpending / accepted / rejected。同意后互相关注
PrivateMessage写入时记下保存天数，到期物理删除
Group创建者是用户。成员角色 admin / member
伙伴 · companion_profiles
CompanionProfileUserID 唯一。现在一人一条活跃档案
亲密度等级 1–10，分数 0–100
CompanionMemory同一用户。HeroID 空串是主伙伴
生命 · life_entities
LifeWorld名字唯一
LifeEntityWorldID 存世界名，不是世界表的数字主键
LifeRelationship同一世界里的两个居民。默认 friend，另有亲密度
运行时内存 tick。库是存档。/ws/life 按世界推送
桥。 CompanionProfile.LifeEntityID 默认 0，非 0 时指向一个居民。关系层头像和居民形象是两套字段。机器人用户仍是一条 user，用 IsBot 和 BotAgentKey 标出来。

不要混用

说这个词指不要当成
用户user伙伴、居民、管理台账号
好友申请接受后的互相关注LifeRelationship
伙伴companion_profiles 一行酒馆多角色、Life 居民
居民life_entities 一行用户的社交身份
世界life_worlds 的名字社区群组
钱包和 VIP 挂在用户上，不在这三张图的中心。多角色以后是多行加活跃标记，不要再写死全局只有一个伙伴。
