# 架构调整说明

日期：2026-05-18

## 当前结论

当前项目后端应遵循：

`API -> RPC -> DB`

其中：

- API 层负责 HTTP 路由、鉴权、参数适配、响应转换
- RPC 层负责核心业务逻辑与数据库访问
- DB 层负责结构化业务数据存储

## 本轮 AI 相关调整

本轮已完成的 AI 架构纠偏：

- 移除 API 层对数据库的直接依赖
- AI 用户配置改为 API 调 RPC
- AI 资源接口改为 API 调 RPC
- RPC 层新增 AI 配置与资源相关 proto / logic / server 映射
- 重新生成 `super.proto` 对应 pb 代码

## AI 配置当前分层

服务端配置：

- `/api/ai/config`
- `/api/ai/providers`
- `/api/ai/agents`
- `/api/ai/lorebooks`

职责划分：

- API：鉴权、HTTP 入参、出参兼容
- RPC：读写 `AiUserConfig`
- DB：存储 Provider / Agent / Lorebook / User Persona / Preferences

## 为什么不是 API 直接连 DB

如果 API 直接访问数据库，会带来几个问题：

- 业务逻辑分散在 API 层和 RPC 层
- 后续复用困难
- 架构边界变乱
- 与项目 **Kratos 分层**（`moehttp` → `service` → `biz` → `data`）不一致

所以 AI 这部分已统一回到 RPC 持有数据库访问权。
