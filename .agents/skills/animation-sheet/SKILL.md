# Animation Sheet Skill

## Purpose

将 AI 生成或用户提供的无规则图片、图集、视频帧，整理为可被任意 2D 工具或引擎直接使用的透明网格序列帧。

本 Skill 的产品目标是一个统一的“序列帧整理工作台”，不是角色换装器、AI 人设生成器或某个引擎的专用编辑器。最终交付物必须是调整完成的 RGBA `spritesheet.png`，以及描述网格、动画行、帧顺序和时序的可重导入 JSON。

## Product Boundary

- 编辑器独立于 Godot、Unity、Phaser、Flame、LPC 和任何具体运行时。
- Godot 是重要验收目标：导出的 PNG 必须可以通过 `Sprite2D` / `AnimatedSprite2D` 的网格区域直接裁剪使用；不把 Godot 私有场景或脚本写进通用输出。
- 输入支持 PNG、JPG、JPEG、WebP、本地视频，以及带 JSON 描述的 Sprite Sheet。
- JPG/JPEG/WebP 只作为输入格式；导出统一为透明 RGBA PNG。原图无透明通道时，不得静默假设背景已经清理。
- 工作台只有一条连续主流程：导入 → 帧池 → 统一画布与对齐 → 动画编排 → 预览 → 导出 → 重导入验证。
- 不把“角色生成器”“Sprite 修复器”“动画预览器”做成互相割裂的项目或入口；它们只能是同一工作台内的阶段和面板。

## Reference Direction

借鉴 `XSXB-Frame-Tuner` 的 Lite 模式：

- 原始帧池与动画组分离；一张帧可被多个动画组复用。
- 以角色全部动作的可见像素范围计算统一画布和稳定原点，避免动作切换时角色跳位。
- 同时支持散帧输入、已有 Sheet + JSON 输入和视频抽帧输入。
- 帧级缩放、偏移、禁用、顺序和时长可以被保存，并参与最终烘焙。
- 导出时通过系统目录选择器写出可交付文件，不写死到某个游戏项目目录。
- `spritesheet.png` 是最终可用资产，JSON 是解释和重导入依据，不以浏览器预览截图作为交付物。

## Non-Negotiable Boundaries

- 不绑定服装槽位、角色商品 ID、官方 avatar pack、LPC layer 或固定 64/128 格角色协议。
- 不用复制、往返、静态缩放或平移冒充真实新动作；此类结果必须标记为“动作草稿”，不可宣称为正式动画。
- 原始帧池和动画行必须分离。
- 从动画行移除帧，不得误删帧池中的原始帧。
- 从帧池删除帧时，必须同步安全重映射所有动画行引用、变换和帧级元数据。
- 所有动作行共享统一 cell 宽高和角色原点；不得每个动作单独裁剪成不同尺寸。
- 每次导出必须生成完整网格 PNG，不能只导出散乱帧或只生成预览。
- 不添加没有完整导入、编辑、导出、重导入和验证闭环的 UI 功能。

## Canonical Workflow

```text
导入 PNG/JPG/WebP、已有 Sheet + JSON 或视频
→ 保留原始名称与顺序，建立统一帧池
→ 清理背景（明确操作）并检查透明度
→ 计算全角色统一画布、cell 尺寸和稳定原点
→ 对每帧调整缩放、偏移、旋转、禁用状态
→ 创建动画行，编排帧索引、FPS、循环和行顺序
→ 在同一工作台预览当前帧、动画行和最终网格
→ 导出 spritesheet.png + spritesheet.json
→ 重新导入导出物，检查尺寸、透明、帧矩形、顺序和时序
```

## Unified Workbench UI

页面必须围绕一个项目和一个角色素材集组织，不再用“角色生成器 / Sprite 修复器”作为两个产品入口。

- 顶部：素材集名称、未保存状态、导入、保存草稿、导出最终 Sheet。
- 左侧：输入来源与素材集管理；支持散帧、Sheet、视频三种导入方式。
- 中央：统一画布编辑区，显示透明网格、cell 边界、原点、当前帧和前后参考帧。
- 底部：原始帧池时间线；支持排序、禁用、删除、拖入动画行。
- 右侧：当前帧 / 当前动画行检查器，编辑缩放、偏移、旋转、时长、FPS、循环和动画名。
- 预览和导出是同一数据源的不同视图；预览不能拥有一套独立的角色或帧数据。
- 角色装扮组合、AI 角色卡、家具内容包属于其他产品域，不进入本工作台主流程。

## Output Contract

### `spritesheet.png`

- PNG，RGBA，透明背景。
- 所有 cell 使用同一 `frameWidth` / `frameHeight`。
- 每一行动画占一行；每一列是该行的一个最终帧。
- 每个最终帧已经应用统一画布、原点、缩放和偏移，可以直接被网格裁剪。
- 空白补位必须透明，不得使用棋盘格或预览背景写入图片。

### `spritesheet.json`

使用引擎无关的 `sprite-animation-v1` 结构，至少包含：

- `image`、`format`、`canvas.width`、`canvas.height`；
- `frameLayout.frameWidth`、`frameLayout.frameHeight`、`columns`、`rows`；
- `anchor` 或等价的稳定原点信息；
- 每个动画行的稳定 `id`、`label`、`row`、帧索引/矩形、`fps`、`loop`；
- 每个最终帧到原始帧的映射，便于追溯和重导入。

JSON 不得依赖 Godot API、Flutter 类型或 admin 页面内部状态。

## Editing Rules

1. 导入时保留文件名、来源和原始顺序；已有 Sheet + JSON 优先使用 JSON 的裁剪矩形和帧时长。
2. 任意帧可以被多个动画行复用；动画行内部排序不改变帧池索引。
3. 删除或重排帧时，统一更新引用、变换、音频和导出映射。
4. 背景清理必须是显式操作，并提供清理前后对照或可恢复结果。
5. 统一画布必须覆盖当前素材集所有需要导出的动画行和可见图层。
6. 导出前阻断空动画行、越界索引、不同 cell 尺寸、丢失帧和超过图片尺寸上限的结果。
7. 合成、镜像、缩放或位移生成的帧只能进入草稿流程，并在 manifest 中标记来源。

## Implementation Order

1. 将当前 `SpriteRepairPage` 的帧池、动画行、变换、透明画布和 Sheet 导出能力定义为核心域模型。
2. 将 `SpriteStudioPage` 改为单一序列帧工作台，消除角色组合器与 Sprite 修复器的产品分叉。
3. 统一导入协议：散帧、Sheet + JSON、视频抽帧都进入同一帧池。
4. 统一编辑协议：所有调整都写入同一素材集状态，预览和导出只消费该状态。
5. 固化 `sprite-animation-v1` manifest，并实现导出物重导入校验。
6. 用真实 AI 生成的多动作素材验证：导入 → 调整 → Sheet 导出 → Godot 网格裁剪 → 回到工作台重导入。

## Acceptance Checklist

- [ ] PNG、JPG、JPEG、WebP 都能导入；视频可抽帧并进入帧池。
- [ ] 已有 Sheet + JSON 能按 JSON 裁剪并保留帧时长。
- [ ] 可以创建至少两个动画行，且同一帧可以复用。
- [ ] 可以从动画行移除帧而不影响其他动画行。
- [ ] 可以从帧池删除帧并安全清理所有引用。
- [ ] 可以逐帧调整缩放、偏移、旋转、禁用和时长。
- [ ] 全部动画共享统一 cell 尺寸和稳定原点。
- [ ] 输出 PNG 是透明、可直接网格裁剪的完整 Sheet。
- [ ] 输出 JSON 能解释每一行动画的位置、帧数、FPS、循环和来源映射。
- [ ] 导出物可以重新导入并恢复动画结构。
- [ ] 至少用一组真实 AI 序列帧完成 Godot 网格裁剪验收。

## Definition Of Done

只有当真实素材完成“导入 → 归纳 → 统一画布 → 调整 → 网格 PNG 导出 → JSON 重导入 → Godot 网格裁剪”闭环后，才能标记为完成。只有浏览器中能播放、能下载或能显示预览时，只能标记为实验或草稿。
