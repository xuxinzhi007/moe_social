# Moe Admin Page Layout Rules v1

这份文档定义 `moe-admin` 第一版页面重构规则。目标是先解决后台页面长期存在的几个结构问题：

- 内容区模块只是往下堆，没有章节感
- 左边拥挤、右边留白，宽屏空间没有被正确利用
- 列表页、配置页、总览页共用近似骨架，导致每种页面都“不像它自己”
- 不同开发者或 AI 在没有统一规则时，容易继续复制这种布局问题

## 先分类型，再写页面

所有后台页面在开始实现前，必须先归类，只允许进入以下三种模板之一。

### 1. 列表工作台页

适用：

- 用户列表
- 动态审核
- 评论管理
- 举报处理
- 订单管理
- 反馈列表

标准结构：

1. 页面摘要：说明当前对象、当前筛选结果、关键统计
2. 工具条：搜索、筛选、批量操作
3. 主表格：作为视觉主区域
4. 详情区：统一优先右侧抽屉，其次下方详情区
5. 分页区：固定表格底部

禁止：

- 标题下面直接跟一个大表格，没有摘要层
- 表格和详情区在同一个视觉层里竞争主次

### 2. 策略配置页

适用：

- AI 大脑
- 平台治理
- 应用配置
- 菜单规则

标准结构：

1. 对象头部：当前对象是谁、页面目标是什么、主操作是什么
2. 状态摘要：当前对象的关键状态、数量、异常提示
3. 主工作区：
   - 左列：规则/配置表单
   - 右列：结果分析/预览/风险提示
4. 历史记录区：变化结果、数据记录、时间线

推荐栅格：

- 上部全宽对象摘要
- 中部 `7 / 5` 双栏
- 下部全宽记录流

禁止：

- 选择对象、配置表单、结果记录全部顺序堆叠在单轴上
- 大文本框直接占满页面，但没有承担章节结构

### 3. 总览监控页

适用：

- 运维总览
- RPC 监控
- 数据总览
- 平台概览

标准结构：

1. 核心指标层
2. 状态区 / 图表区
3. 快捷操作区
4. 日志 / 流水线 / 历史区

禁止：

- 指标、状态、操作、日志全部平铺成同样权重的 panel

## 统一栅格规则

### 栅格只允许三种

1. 单栏受控
   适合长表单、说明页、单对象编辑页

2. 双栏 `7 / 5`
   适合配置 + 分析、列表 + 详情

3. 全宽主表格
   适合表格型工作区，详情通过抽屉承载

### 关键约束

- 同一屏内不要混用“上窄列、下全宽、再伪双栏”
- 页面必须有稳定的内容起始线
- 宽屏下的右侧空间必须承担职责，不能只是空白

## 章节规则

页面内容至少有三级：

1. `Page`
2. `Section`
3. `Card`

要求：

- 不能把一堆 Card 直接平铺在 Page 下
- 必须先有 Section，再在 Section 内组织 Card
- Section 之间要有明确的职责名称

## 主操作位置规则

- 页面级主操作：页面标题区右上
- Section 级操作：Section Header 右侧
- 行级操作：表格最右列
- 高危操作：与普通操作视觉分组分离

## 详情承载规则

- 列表页详情：优先右抽屉
- 配置页分析：优先侧边分析区
- 历史数据：优先底部记录区
- 不允许同类页面一会儿下方详情、一会儿跳页、一会儿弹框

## 第一批重构样板

第一版先做三类样板页：

1. `UsersPage`：列表工作台
2. `MoeBrainPage`：策略配置页
3. `OverviewPage`：总览监控页

后续所有页面都必须优先参考这些样板，而不是继续从零拼布局。
